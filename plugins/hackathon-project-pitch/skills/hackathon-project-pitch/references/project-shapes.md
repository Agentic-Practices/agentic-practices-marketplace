# Example Project Shapes — a menu for teams who can't picture what to build

Use this **only when a team is stuck** on *what* to build — when they have a problem but no
form, or when they're staring at a blank page. Offer it as a menu of recognisable starting
points. It is not a required step and not a constraint; a good idea that fits none of these
shapes is still a good idea.

Ask which shape is closest to what they're imagining, then help them scope a demoable slice.

## The shapes

**Internal Web App**
Build an internal tool with a frontend, backend, and data store that replaces a manual
process.
*Example:* a capacity-tracking tool that replaces a manual spreadsheet.
*When it fits:* highly relevant where an organisation has manual internal processes ripe for
replacing.

**API Service**
Design, build, test, and document a REST or GraphQL service that integrates with existing
systems.
*Example:* a service that connects two internal systems so data flows automatically instead
of by copy-paste.
*When it fits:* best suited to strong developer teams.

**Data Pipeline + Dashboard**
Build an ingestion pipeline, a transform layer, and a reporting UI around a real data problem.
*Example:* a delivery dashboard that pulls from several sources and gives leadership
real-time visibility on project health.
*When it fits:* good for internal reporting or operational-data challenges.

**CLI Tool + Test Suite**
Ship a command-line tool with argument parsing, tests, CI config, and published
documentation.
*Example:* a command-line tool that scaffolds a new project to the team's coding standards
automatically.
*When it fits:* suitable when the goal fits this shape — confirm the scope is achievable in
the window.

**Chatbot or AI Agent**
Build a conversational agent with defined skills, a backend, persistent state, and end-to-end
tests.
*Example:* an internal assistant that helps staff draft proposals, scope documents, or status
reports from project inputs.
*When it fits:* highly relevant — directly aligned with the agentic-engineering focus.

**Mobile or Desktop App**
Design, implement, and test a small native or cross-platform app around a specific user need.
*Example:* a lightweight app for a field or on-the-go task that today relies on paper or a
laptop.
*When it fits:* viable if scoped tightly from the outset — the team must define a slice that
can be demonstrated within the hackathon window.
